# Audit outputs for the live-baseline readiness review (2026-09-30)

These files are compact outputs of `scripts/audits/`, produced at code commit `ca26e31`. They hold ids, counts, hashes and aggregate figures, never document text, full prompts or images. The one exception is `live-check-selection/runtime_manifest.livecheck-v1.json`, a subset of the frozen runtime manifest that repeats its question text and document hashes, which are runtime data.

`provenance.json` lists the exact commands, the SHA-256 of every input, tool and output, and which inputs stay local. A hash identifies a file. It is not a backup.

| Path | What it shows |
| --- | --- |
| `prompts/audit_prompts.json` | Runtime-only prompt checks on the 70 prepared records. The trace of files the dry run opened is in it. The traced dry run itself holds full prompts and stays in `.local/work/audits-ca26e31/` |
| `leakage-diagnostic/` | A diagnostic that reads evaluation data. Its output must never feed runtime preparation |
| `cost-full-pilot/`, `cost-live-check/` | Bounds, heuristic estimates and ceiling replays. Estimates are not tokenizer counts or bills |
| `live-check-selection/` | The ids chosen by rule `faar-live-check-v1` and the derived manifest used by the live check |
| `case-review/` | Counts from the structured agent review. It is not human annotation |
| `verify-live-check-on-subset-fake-r1.txt` | The live-check verifier on the fake rehearsal. The provider and endpoint rows fail by design in a fake run |

Local inputs that are not committed: the dry run `.local/work/prompt-preview-ca26e31-candidate/` (regenerated by the first command in `provenance.json`), the unapproved candidate provider config (only local copy, no backup) and the subset evaluation manifest `.local/work/livecheck/evaluation_manifest.livecheck-v1.json` (the frozen evaluation manifest filtered to the 8 ids).
